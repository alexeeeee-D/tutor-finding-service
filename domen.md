# Бизнес-домен. Сервис для поиска репетиторов

**Вариант № 20** (группа 5130904/40101)

## О задаче

Задачей является разработка сервиса, ориентированного на подбор учеников
репетитору и репетитора ученику.

## Формула варианта СМО

`ИБ — ИЗ2 — ПЗ1 — Д10З2 — Д10О4 — Д2П2 — Д2Б1 — ОР1 — ОД2`

| Код | Описание |
|---|---|
| ИБ | Бесконечный источник |
| ИЗ2 | Равномерный закон распределения интервалов поступления |
| ПЗ1 | Экспоненциальный закон обслуживания |
| Д10З2 | Буфер в порядке поступления (FIFO), запись в первое свободное место |
| Д10О4 | Отказ последней поступившей заявке при переполнении буфера |
| Д2П2 | Выбор прибора по кольцу |
| Д2Б1 | Выбор заявки FIFO (первым пришёл — первым обслужен) |
| ОР1 | Автоматический режим — сводная таблица статистики |
| ОД2 | Пошаговый режим — схема модели и состояние системы |

---

## 1. Элементы бизнес-домена

### 1.1. Источник (ИБ, ИЗ2)

Источниками являются **ученики (или их родители)**, которые оставляют
заявки на подбор репетитора. Каждый ученик может формировать новые заявки
в течение всего времени работы платформы, поэтому поток заявок считается
**бесконечным**. Интервалы между поступлениями заявок моделируются
**равномерным законом распределения**.

Примеры источников:

- **Ученик 1** — ищет репетитора по математике (9 класс, ОГЭ)
- **Ученик 2** — ищет репетитора по физике (11 класс, ЕГЭ)
- **Ученик 3** — ищет репетитора по английскому (7 класс, общий курс)

### 1.2. Прибор (ПЗ1) — экспоненциальное обслуживание

Приборами являются **алгоритмы подбора**, которые обрабатывают заявку:
проверяют анкету ученика, подбирают подходящих репетиторов, связывают
стороны. Каждый прибор в один момент времени обслуживает одну заявку.
Время обработки заявки является случайным и моделируется
**экспоненциальным законом распределения**.

Примеры приборов:

- **Модератор 1** — обрабатывает заявки по математике и физике
- **Модератор 2** — обрабатывает заявки по английскому и другим языкам
- **Модератор 3** — универсальный модератор

### 1.3. Буфер (Д10З2) — в порядке поступления

Если заявка не может быть передана на обработку (все модераторы заняты),
она помещается в общую очередь. Запись в буфер выполняется **в порядке
поступления**: заявка занимает первое свободное место, начиная с начала
очереди.

При освобождении места с номером `N` все заявки, стоящие на местах
`N+1, N+2, …`, сдвигаются на одну позицию вперёд. Новая заявка всегда
становится в конец очереди, пока есть свободные места.

Реализация — с помощью очереди (буфер FIFO).

### 1.4. Дисциплина отказа (Д10О4) — последняя поступившая

Если при поступлении новой заявки все позиции буфера заняты, применяется
**отказ последней поступившей заявке**. Заявка, которая меньше всех
простояла в очереди (самая «свежая»), удаляется из системы без обработки.
Новая заявка занимает её место.

Ученик, чья заявка была выбита, получает уведомление:
> «Система перегружена, попробуйте позже».

### 1.5. Дисциплины постановки на обслуживание (Д2П2, Д2Б1)

**Д2Б1 (FIFO) — первым пришёл, первым обслужен**

При освобождении модератора диспетчер выбирает из буфера заявку, которая
дольше всех простояла в очереди. Это классическая очередь: кто раньше
обратился, тот раньше получит репетитора.

**Д2П2 (выбор прибора по кольцу)**

Поиск свободного модератора начинается с текущего указателя и выполняется
циклически. Заявка передаётся первому найденному свободному модератору,
после чего указатель переводится далее по кольцу.

### 1.6. Отображение результатов (ОР1, ОД2)

**Автоматический режим (ОР1):** результаты моделирования выводятся в виде
сводной таблицы, содержащей основные статистические характеристики работы
системы:

- Количество сгенерированных и обработанных заявок
- Число отказов
- Среднее время ожидания и обслуживания
- Загрузка модераторов

**Пошаговый режим (ОД2):** отображается формализованная схема модели и
текущее состояние системы. На каждом шаге (особом событии) показывается:

- Текущее состояние буфера
- Занятость модераторов
- Положение указателей
- Какая заявка обрабатывается

### 1.7. Заявка

**Заявка** — это запрос на подбор репетитора, сформированный учеником.
Заявка хранит:

- Принадлежность к ученику-источнику
- Момент поступления в систему
- Данные, необходимые для расчёта времени ожидания, обслуживания и
  пребывания в системе
